# 管理画面のセットアップ手順

管理画面：https://toolbox.lucke.jp/admin/

道具箱の利用状況（見た人・使った人）と、各アプリの登録者数などを1画面で見るための設定です。
Cloudflare の画面のボタン名は変わることがあります。見つからないときは、近い名前のメニューを探してください。

---

## 1. Cloudflare：データベース（D1）を作る（約2分）
1. Cloudflare ダッシュボードの左メニュー「ストレージとデータベース」→「D1 SQL データベース」→「作成」
2. 名前を `toolbox-stats` にして作成（表は最初の記録のときに自動で作られるので、SQL を書く必要はありません）

## 2. Cloudflare：道具箱のプロジェクトにつなぐ（約3分）
1. 「Workers & Pages」→ `toolbox-app` →「設定」→「バインディング」→「追加」→「D1 データベース」
2. 変数名を `DB`（半角大文字）、データベースに `toolbox-stats` を選んで保存
3. 同じ「設定」の「変数とシークレット」→「追加」で、種類を「シークレット」にして次を登録

| 名前 | 値 |
|---|---|
| `ADMIN_PASSWORD` | 管理画面のパスワード（8文字以上。長めの文字列がおすすめ） |

4. 設定は**次の公開から**反映されます。GitHub Desktop で Push するか、「デプロイ」画面から最新のデプロイを「再試行」してください。

この時点で、道具箱の利用状況が記録・表示されるようになります。

## 3. Firebase のアプリをつなぐ（1アプリ約5分）
アプリごとに、**読み取り専用**の鍵を作って Cloudflare に登録します。

1. https://console.cloud.google.com を開き、上部のプロジェクト選択でそのアプリの Firebase プロジェクトを選ぶ
2. 左メニュー「IAM と管理」→「サービス アカウント」→「＋ サービス アカウントを作成」
3. 名前を `toolbox-stats` にして「作成して続行」
4. ロールに次の2つを追加して「完了」
   - **Firebase Authentication 閲覧者**
   - **Cloud Datastore 閲覧者**
5. 一覧から作ったアカウントを開き、「鍵」タブ →「鍵を追加」→「新しい鍵を作成」→「JSON」→「作成」
6. ダウンロードされた JSON ファイルをメモ帳で開き、**中身をすべて**コピー
7. Cloudflare の「変数とシークレット」に、種類「シークレット」で登録

| アプリ | 名前 |
|---|---|
| Lucke Inventory | `FB_INVENTORY` |
| HACCP管理システム | `FB_HACCP` |
| テイクアウト予約 | `FB_RESERVE` |
| 複式簿記 記録ツール | `FB_BOKI` |
| たすけてグリーン | `FB_SOSGREEN` |

8. 登録が終わったら、ダウンロードした JSON ファイルはパソコンから削除する（Cloudflare に入っていれば不要。チャットやメールには貼らない）

> 「鍵の作成が組織のポリシーで無効」と表示される場合は、Firebase コンソールの「プロジェクトの設定」→「サービス アカウント」→「新しい秘密鍵を生成」で作った鍵でも動きます（ただし、その鍵は全権限を持つので取り扱いに注意）。

## 4. Supabase のアプリをつなぐ（FoodLabel・NekoMap）
Claude が Supabase に接続できる状態であれば、集計用の関数の追加と合言葉の発行まで Claude が行います。あなたがやるのは、発行された合言葉を Cloudflare に登録することだけです。

| アプリ | 名前 |
|---|---|
| FoodLabel Pro | `SB_FOODLABEL_TOKEN` |
| NekoMap | `SB_NEKOMAP_TOKEN` |

自分で設定する場合は `docs/sql/README.md` を参照してください。

## 5. 確認
1. https://toolbox.lucke.jp/admin/ を開いてパスワードでログイン
2. アプリのカードに「未接続」や「エラー」が出ていないか確認（「アプリの数字を取り直す」で再取得）
3. 自分の操作で数字を増やしたくない端末では、画面下の「この端末の利用を道具箱の集計に含めない」にチェック

---

## よくあるエラー

| 表示 | 原因と対処 |
|---|---|
| ログインで「パスワードが未設定」 | `ADMIN_PASSWORD` が未登録か、まだ再デプロイしていない |
| 「D1 データベース（変数名 DB）がバインドされていません」 | 手順2のバインディングを確認して再デプロイ |
| 「ユーザー一覧を読めません（PERMISSION_DENIED）」 | ロール「Firebase Authentication 閲覧者」が付いていない |
| 件数が「取得失敗」 | ロール「Cloud Datastore 閲覧者」が付いていない、またはコレクション名が違う（`server/apps.js`） |
| 「合言葉が違います」 | Cloudflare の `SB_…_TOKEN` と、データベースに登録した合言葉が一致していない |
| ログインの失敗が続いた | 同じ回線から1時間に10回失敗すると、1時間ロックされる |

## アプリを追加するとき
`server/apps.js` に1件足し、上の手順で鍵（または合言葉）を登録します。Firestore で件数を数えたいコレクションは `counts` に書きます。
